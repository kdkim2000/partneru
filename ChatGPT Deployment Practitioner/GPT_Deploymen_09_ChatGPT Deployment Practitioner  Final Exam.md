**Question 1:** A seller suggests that customer success managers will probably be the first ChatGPT cohort, but the business owner has not confirmed that group. How should the deployment team classify this statement?

- A blocking constraint that automatically requires a no-go decision
- **A reasonable assumption that must be validated before it supports a commitment** ✓ Correct
- Confirmed evidence, because the seller named a specific cohort
- An unknown, because no plausible cohort has been identified

The course defines reasonable assumptions as plausible information that has not yet been validated, and it lists an initial user group as an example. Such assumptions can support planning, but they must not be treated as confirmed facts.

**Question 4:** Which launch-scope statement is strongest for a first ChatGPT deployment motion?

- Begin with every legal knowledge workflow so the team can discover which one gains the most usage
- Delay scope decisions until workspace setup is complete and users have explored the product

The course says launch scope should define the first workflow and cohort, customer- and partner-side owners, dependencies, validation period, governance expectations, measurement approach, and the decision after the first period. The scope should be narrow enough to activate but meaningful enough to produce useful evidence.

**Question 5:** Which example is a lagging signal for a launch workflow?

- Target users try the approved workflow for the first time after completing workflow enablement
- **The workflow shows fewer revision cycles and more consistent outputs** ✓ Correct
- Target users join the workspace
- Users complete workflow enablement

Leading signals show whether activation is beginning, such as joining, completing enablement, or trying the workflow. Lagging signals help judge whether the workflow is producing value, including fewer revision cycles and better consistency or quality.

**Question 8:** A Workspace Agent that updates the contract system may be useful later, but the first activation can proceed using approved static materials. How should the readiness checklist treat the Workspace Agent?

- Mark the workspace blocked until the Workspace Agent is enabled
- **Mark it deferred and keep it visible until its need and readiness are confirmed** ✓ Correct
- Remove the Workspace Agent because deferred dependencies should not appear in the checklist

An App, plugin, or Workspace Agent should not become a blocker unless the first workflow depends on it. Because approved static materials can support the first activation, the proposed Workspace Agent should remain visible as a deferred dependency. Its need, access, connection ownership, action approvals, logging, and escalation requirements can be validated before later use.

**Question 9:** The first workflow requires policy guidance, but no source owner has been identified and the content's approval cannot be confirmed. Activation cannot proceed without that guidance. Which checklist status is appropriate?

Blocked applies when activation cannot proceed because a required owner, approval, source, access path, or dependency is missing. Needs validation is used when an item may still be usable pending confirmation; here the missing required source owner and approval prevent activation.

**Question 12:** Which set provides the most balanced early success evidence for an activation workflow?

**Question 13:** A proposed enablement session demonstrates general prompting features but cannot identify the approved workflow, audience, behavior change, support route, or feedback loop it serves. What should the team do?

**Question 16:** Output quality is inconsistent because the approved source set is outdated. Which improvement action best matches the root cause?

- Repeat the same general training and reinforce existing guidance without changing source ownership or content
- Remove human review so users can complete the workflow faster
- **Update the approved sources and ownership, revise workflow guidance, then review another output sample** ✓ Correct

Not every problem is an enablement problem. When outdated or unclear source material causes poor output quality, the practical response is to correct the source set and ownership, update guidance, and then review new evidence before expansion.

**Question 17:** One operations region has successfully adopted human-reviewed procedure summaries from approved SOPs. Which expansion candidate is generally the safest next step?

- Every employee across all functions using ChatGPT for general productivity
- **Another operations region using the same workflow and review model after confirming dependencies** ✓ Correct
- A customer-facing incident-response workflow that introduces new data, review, escalation, and policy boundaries
- An unrelated function that requires a different source set and support model

The safest scaling candidate is often close to the workflow that already produced evidence. A similar region with the same source and review pattern carries fewer new dependencies than a customer-facing or unrelated workflow, though readiness still must be confirmed.
