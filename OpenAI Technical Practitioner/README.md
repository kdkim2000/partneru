# OpenAI Technical Practitioner

제품 친숙도를 실질적인 기술 판단력으로 확장시키는 과정입니다. 고객 워크플로우를 신뢰할 수 있는 솔루션 경로로 연결하고, 더 나은 구현 질문을 던지며, 트레이드오프를 조기에 파악하고, 전문가 검증이 필요한 시점을 인식하는 방법을 다룹니다. ChatGPT/Codex/API Expert 3개 트랙에 공통으로 포함되는 과정입니다. 총 7개 차시(강의 영상 7편 + 강의 노트 7편)로 구성되어 있으며, 마지막 차시는 최종 시험입니다.

## 차시별 핵심 내용

### 01 — Technical Fluency Orientation

제품 친숙도와 실질적인 기술 판단력을 구분하고, 사용자/제품 표면·필요 역량/아키텍처·배포/운영 방식이라는 3축 라우팅 모델로 기술 기회를 조기에 책임감 있게 라우팅하는 방법을 배웁니다. 향후 고객·구현 대화에서 재사용할 Technical Fluency Navigator를 (선택적으로) 작성합니다.

### 02 — Technical Implementation Foundations

시스템이 어떻게 통신하고, 솔루션이 어디서 실행되고, 데이터가 어떻게 이동하고, 품질이 어떻게 테스트되는지에 대한 구현 기초를 다룹니다. Responses API가 신규 커스텀 API 구현의 기본 프리미티브로 권장되는 이유를 설명하고, Implementation Readiness Snapshot을 작성합니다.

### 03 — Model Selection and Solution Patterns

"어떤 모델을 써야 하나요?"라는 질문에 모델 이름이 아닌 태스크 형태(task shape)로 답하는 방법을 배웁니다. 모델 클래스별 강점과 트레이드오프, API 모델 선택의 의사결정 요인, 흔한 고객 요구를 반복 가능한 솔루션 패턴에 매핑하고 검증 근거를 판단하는 방법을 다룹니다.

### 04 — Platform Capabilities and Developer Tools

기능 목록이 아닌 워크플로우 필요에 따라 플랫폼 역량을 선택하는 방법을 다룹니다. Responses API를 기본 시작 프리미티브로 삼고, Structured Outputs, File Search, tool calling, Agents SDK, MCP, evals, Audio/Realtime, Codex 등이 언제 필요한지 역할별로 구분합니다.

### 05 — Architecture Patterns & Solution Blueprints

검색 기반 생성(RAG), 에이전틱 오케스트레이션, 휴먼 리뷰, 멀티모달/음성 상호작용, 엔터프라이즈 통합 등 OpenAI 솔루션의 공통 아키텍처 패턴을 인식하고, 이를 워크플로우·사용자·데이터·컨텍스트·툴·거버넌스·성공 지표를 연결하는 첫 단계 Solution Blueprint로 구성하는 방법을 배웁니다.

### 06 — Security, Governance & Data

데이터 민감도·소스·소유권·접근, 권한과 역할 경계, 툴/액션 리스크, 승인·감사·가드레일·관찰가능성 필요 지점을 식별합니다. 구현 준비가 된 가정과 전문가 검증이 필요한 이슈를 구분하여 Security, Governance & Data Readiness Recommendation을 작성합니다.

### 07 — Final Exam

전체 과정 내용을 종합하는 20문항 객관식 시험입니다 (16문항 이상 정답 시 통과). 각 문항 해설에 근거가 된 차시가 명시되어 있습니다.

## 학습 순서
